extension/chrome — bookmark auto-capture · triage prototype

Should an unmatched bookmark fall back to a generic Link job instead of being rejected?

detect_pipeline() (src/utils/validators.py) already recognizes short/long video, GitHub repos, documents, and allowlisted article domains. Anything else today returns "rejected" — no job, silently dropped — unless the caller passed an explicit fallback-capable intent of link or capture (src/intake/router.py). The extension's Ctrl+Shift+1 command now sends capture; plain Telegram and dashboard pastes still default to automatic, so they do not get this fallback.

The change on the table: when nothing matches, fall back to the generic Link pipeline (already a first-class content_type — same create_and_enqueue_job() call every other pipeline uses) instead of hard-rejecting. This page ports the real matcher rules to JS 1:1 and lets you feel out whether that fallback is right — including the uncomfortable edge case where the pipeline didn't just fail to recognize the URL, but deliberately excluded it (a GitHub gist, an org-only URL, an Instagram photo carousel). Should those get the same free pass into Link, or not?
